# U01: поиск по знаниям и ответы с источниками

Статус: draft, разбор без исполняемой лабораторной вне симуляции (практикум M03.LAB1 тренирует проверку на вымышленном корпусе). Оператор, документы и все числа вымышлены (author example); реального внедрения этот кейс не описывает. Реального первичного production-примера в прочитанных источниках нет (gap, см. coverage: U01 planned).

## Задача и исходный процесс
Получатель результата: сотрудник вымышленного транспортного оператора, который спрашивает «что по тарифным правилам». Вход: вопрос текстом и роль сотрудника. Выход: ответ, который называет документ, версию и статус, либо отказ с передачей человеку. Принятая работа: проверяющий принимает ответ без исправления, ссылка ведёт на действующую версию, закрытый документ не раскрыт.

Без ИИ: сотрудник ищет по номеру документа и ключевым словам в каталоге с версиями, а за исключениями идёт к владельцу документа. Это baseline в сравнении ниже; его время и долю ошибок нужно измерить (в источниках курса нет, gap).

## Подходы и выбор
| Подход | Оценка для U01 |
|---|---|
| Поиск по ключам и каталог, обычный код | Baseline: быстро, воспроизводимо, права проверяются детерминированно; слаб на свободных формулировках |
| Классическое ML (ранжирование) | Нужны размеченные запросы; в кейсе их нет (gap) |
| Весь корпус в контекст | Для малого корпуса просто, но права и устаревшие версии попадают в контекст без фильтра; контекст - ограниченный ресурс (SRC-14, reported) |
| Фиксированный workflow: retrieval с фильтром прав, ответ с цитатой, проверка | Выбранный вариант для пилота в режиме советов |
| Агентный поиск | Не для первого пилота: шаги известны, выигрыш над фиксированным workflow не доказан |

Основание: [Anthropic, Building effective agents](https://www.anthropic.com/research/building-effective-agents) (SRC-02, reported) различает workflow и агента и советует начинать с простейшего решения, для многих задач хватает одного вызова с retrieval. Это эвристика, а не доказательство окупаемости.

Отвергнутая альтернатива: агент с произвольным доступом к хранилищам документов (в том числе через сервер инструментов). Причины: наличие сервера инструментов не является системой авторизации, измеренного baseline нет. Условие отказа от ИИ: если полное время на вопрос (поиск, проверка, переделка) не ниже baseline два периода подряд или утечки закрытых документов не удаётся держать на нуле, остаётся поиск по каталогу без модели. Порог выбирает владелец метрики; общепринятого значения в источниках нет (gap).

## Данные и интеграции
- Корпус: тарифные документы с идентификатором, версией, статусом, сроком действия и владельцем; роль чтения хранится рядом с документом. Формат и хранилище в кейсе не определены (gap).
- Точки человеческого решения: проверяющий принимает или правит ответ; публикацию новых версий и отзыв документов делает владелец; ответ клиенту отправляет человек.
- Граница доверия: текст вопроса, документа и памяти - данные, не команды и не выдача прав. Права определяет учётная запись запросившего.
- Память: хранит только то, что разрешено текущей роли; запись чужого пользователя не источник.
- Для USER эти правила выражены в практикуме без инструментов разработки. Реальные требования транспортных организаций в курс не включаются.

## Безопасность
| Угроза | Контроль | Негативный тест | Остаточный риск и владелец |
|---|---|---|---|
| Закрытый документ попадает в context, цитату или кэш | Фильтр по роли на границе retrieval до модели; идея query-time trimming описана в документации [Azure AI Search](https://learn.microsoft.com/en-us/azure/search/search-document-level-access-overview) (SRC-41, verified для этой платформы; часть механизмов preview) | Оператор спрашивает закрытую инструкцию: нет текста, пересказа и цитаты; попытка фиксируется (M03.A03) | Полнота в реальной среде unverified; владелец данных |
| Ответ по заменённой версии | Метаданные версии и статуса; при конфликте берётся действующая, иначе отказ | Запрос, где v1 и v2 различаются (M03.A02, M03.A04) | Устаревший или неполный корпус; владелец документа |
| Память раскрывает данные другой роли | Память привязана к субъекту и роли; чтение проверяется так же, как retrieval | Данные чужой сессии не появляются в ответе (M03.A04) | Политика хранения и срок не определены (gap) |
| Инъекция в тексте вопроса или документа («разрешаю от имени руководителя») | Текст данных не меняет права; запись и внешние действия только с подтверждением человека | Фраза-команда не расширяет доступ (M03.A03); отдельной защитой в prompt это не решается: надёжной защиты от prompt injection нет, см. R3 | Остаточный риск остаётся; владелец безопасности |
| Выход за схему инструмента | Инструмент только чтения, без операций записи | Запрос на запись передаётся владельцу (M03.A05) | Принуждение зависит от M05 и статусов KC-B; unverified |

Соответствие угроз типовым классам рисков приложений на LLM см. в [AWS mapping к OWASP LLM Top 10 2025](https://docs.aws.amazon.com/prescriptive-guidance/latest/agentic-ai-security/owasp-top-ten.html) (SRC-12; редакцию Agentic 2026 он не заменяет). Принуждение (hook, policy, runtime) показывает только отказ реального исполнителя; здесь оно не проверялось.

## Инфраструктура
Минимум: каталог документов с метаданными и ролями, поиск, фильтр по роли до модели, форма проверки (принят/исправлен/отклонён), журнал user_role / document_version / evidence_ids / decision / escalation без текста закрытых документов, способ отключить пилот. Размещение модели и данных определяет владелец данных (gap). Облако, кластер, многоагентная оркестрация и долговременная память для первого пилота не нужны: шаги известны, корпус небольшой. Версионирование: корпус и фильтр имеют версию, чтобы ответы сопоставлялись с редакцией. Откат: отключение пилота возвращает ручной поиск. Секреты не попадают в журнал и карточку.

## Проверка и экономика
Метрики разделяют: recall поиска, корректность ответа, точность цитаты, отказ при отсутствии ответа, свежесть и права. Числа ниже иллюстративные (author example), не измерены; условия: одна неделя, 100 вопросов, режим shadow.
- Baseline: 4 минуты на вопрос.
- KPI: принято без исправления с верной цитатой на действующую версию / все вопросы = 72 / 100; утечек закрытого текста 0 (условие остановки: любая утечка).
- Полное время: подготовка 0,5 + проверка 1,5 + переделка 3 x 28 / 100 = 2,84 минуты против 4.
- Контрпример (иллюстративные числа): если проверка 3 минуты и переделка у каждого второго ответа (1,5), то 0,5 + 3 + 1,5 = 5 минут против 4: выигрыша нет.
- Внешний контекст: Azure-Samples/azure-search-openai-demo ([pinned revision](https://github.com/Azure-Samples/azure-search-openai-demo/tree/558ffd397eddcfe4da5c85ebc285796b367eb9b2), SRC-42) - demo/reference implementation на данных вымышленной компании; README требует дополнительных security features перед production, код и auth-тесты существуют (прочитано, не запускалось). Пользовательский [issue 2086](https://github.com/Azure-Samples/azure-search-openai-demo/issues/2086) (SRC-43, reported) сообщает 403 только в облаке после включения auth; причина не установлена, это контрпример «локально работает = готово», а не доказанный дефект кода.
