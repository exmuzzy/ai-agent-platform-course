# Глоссарий

Термины курса простыми словами. Роли: U — USER, B — BUILDER, E — ENGINEER. «Модуль» — где термин впервые вводится (M00–M09, см. [учебную программу](curriculum.md)). Определения описывают понятия курса, а не свойства конкретного продукта.

| Термин | Определение | Роли | Модуль |
|---|---|---|---|
| <a id="t01"></a>**Агент** | Программа, где модель сама выбирает следующие шаги и вызывает инструменты, пока не достигнет цели или лимита. | U B E | M00 |
| <a id="t02"></a>**Harness** | Обвязка вокруг модели: инструкции, инструменты, права, проверки и журнал, превращающие модель в рабочего исполнителя. | U B E | M00 |
| <a id="t03"></a>**Kernel (ядро)** | Общая часть harness с правилами, хуками и политиками; клиентские проекты строятся поверх неё. | B E | M00 |
| <a id="t04"></a>**Модель** | Обученная нейросеть, которая по тексту на входе выдаёт текст на выходе. | U B E | M00 |
| <a id="t05"></a>**Промпт** | Текст-запрос к модели; это просьба, а не гарантия исполнения. | U B E | M00 |
| <a id="t06"></a>**Контекст** | Всё, что модель видит в одном обращении: инструкции, история, документы, результаты инструментов. | U B E | M00 |
| <a id="t07"></a>**Окно контекста** | Предельный объём контекста, который модель способна обработать за раз. | B E | M03 |
| <a id="t08"></a>**Токен** | Единица текста для модели и для расчёта цены; примерно часть слова. | U B E | M00 |
| <a id="t09"></a>**Инструкции (AGENTS.md)** | Файл с правилами работы агента в проекте; агент может его не выполнить, поэтому он не заменяет проверки. | B E | M00 |
| <a id="t10"></a>**Skill (навык)** | Пакет инструкций и вспомогательных файлов для конкретной процедуры, подключаемый по необходимости. | B E | M02 |
| <a id="t11"></a>**Tool (инструмент)** | Функция с описанным входом и выходом, которую агент может вызвать: поиск, чтение файла, запрос к API. | U B E | M02 |
| <a id="t12"></a>**MCP** | Открытый протокол подключения инструментов и источников данных к агентам по единому контракту. | B E | M02 |
| <a id="t13"></a>**Hook (хук)** | Скрипт, который harness запускает в определённый момент работы; советующий хук подсказывает, блокирующий может запретить действие. | B E | M05 |
| <a id="t14"></a>**Guard (гвард)** | Блокирующая проверка, отклоняющая недопустимое действие вне промпта. | B E | M05 |
| <a id="t15"></a>**Policy (политика)** | Машинно читаемое правило о том, что разрешено, запрещено или требует человека. | B E | M05 |
| <a id="t16"></a>**Принудительность** | Свойство правила действительно выполняться средой, а не только быть записанным в тексте. | B E | M05 |
| <a id="t17"></a>**Least privilege** | Принцип наименьших прав: агент получает только доступ, нужный для задачи. | U B E | M05 |
| <a id="t18"></a>**Sandbox** | Изолированная среда исполнения с ограничениями на файлы, сеть и процессы. | B E | M05 |
| <a id="t19"></a>**Egress** | Исходящий сетевой трафик; его ограничивают, чтобы данные не уходили наружу. | E | M05 |
| <a id="t20"></a>**Workflow** | Фиксированная последовательность шагов с заранее известной логикой, где модель выполняет часть шагов. | U B E | M02 |
| <a id="t21"></a>**Single-agent** | Схема, где один агент ведёт задачу от начала до конца. | B E | M02 |
| <a id="t22"></a>**Multi-agent** | Схема с несколькими агентами; стоит дороже и сложнее, поэтому оправдана не всегда. | B E | M02 |
| <a id="t23"></a>**Оркестрация** | Управление порядком, ограничениями и передачей данных между шагами или агентами. | B E | M06 |
| <a id="t24"></a>**DAG** | Граф шагов со стрелками зависимостей без циклов; шаг запускается, когда готовы его предшественники. | E | M06 |
| <a id="t25"></a>**Hard stop** | Жёсткая остановка по бюджету или лимиту, которую агент не может обойти. | B E | M06 |
| <a id="t26"></a>**Durable state** | Состояние выполнения, сохранённое так, что после сбоя работу можно продолжить или воспроизвести. | E | M06 |
| <a id="t27"></a>**Replay** | Повторное воспроизведение сохранённого хода выполнения для проверки или восстановления. | E | M06 |
| <a id="t28"></a>**Идемпотентность** | Свойство операции: повтор с тем же ключом не создаёт второго эффекта. | B E | M05 |
| <a id="t29"></a>**Fencing token** | Возрастающий номер, по которому хранилище отвергает записи устаревшего исполнителя. | E | M06 |
| <a id="t30"></a>**Dry-run** | Пробный запуск, показывающий, что было бы сделано, без реальных изменений. | U B E | M05 |
| <a id="t31"></a>**Reconcile** | Сверка фактического состояния системы с ожидаемым вместо слепого повтора после сбоя. | E | M06 |
| <a id="t32"></a>**Pin** | Закрепление точной версии (например, коммита) ядра или зависимости, чтобы поведение не менялось само. | B E | M00 |
| <a id="t33"></a>**Lock / манифест** | Файл, фиксирующий состав и версии установленных частей клиента. | B E | M06 |
| <a id="t34"></a>**Rollback (откат)** | Возврат к предыдущей рабочей версии кода, модели или настроек. | B E | M06 |
| <a id="t35"></a>**Canary** | Выпуск изменения сначала на малой доле трафика для раннего обнаружения проблем. | E | M06 |
| <a id="t36"></a>**RAG** | Подход, где перед ответом из разрешённых источников извлекаются фрагменты и подаются модели как опора. | U B E | M03 |
| <a id="t37"></a>**Retrieval** | Поиск релевантных фрагментов в хранилище по запросу. | B E | M03 |
| <a id="t38"></a>**Provenance (происхождение)** | Сведения о том, откуда взяты данные и кто их изменял. | B E | M03 |
| <a id="t39"></a>**ACL** | Список прав: кто какие документы может читать; поиск обязан его учитывать. | B E | M03 |
| <a id="t40"></a>**Отказ при отсутствии evidence** | Корректный ответ «не знаю», когда в разрешённых источниках нет подтверждения. | U B E | M03 |
| <a id="t41"></a>**Eval** | Повторяемая проверка качества системы на наборе заданий с критериями оценки. | U B E | M04 |
| <a id="t42"></a>**Грейдер** | Код или правило, которое оценивает результат; детерминированный грейдер не использует LLM. | B E | M04 |
| <a id="t43"></a>**Oracle** | Эталонное верное решение, которое грейдер обязан принять. | E | M04 |
| <a id="t44"></a>**Mutant** | Намеренно испорченное решение, которое грейдер обязан отклонить. | E | M04 |
| <a id="t45"></a>**Empty (пустое решение)** | Прогон без изменений: грейдер не должен засчитывать его как успех. | E | M04 |
| <a id="t46"></a>**Tamperer** | Тестовый исполнитель, пытающийся подделать оценку; проверяет защиту грейдера. | E | M04 |
| <a id="t47"></a>**Holdout** | Отложенная часть задач, скрытая от разработки и настройки, для честной итоговой оценки. | B E | M04 |
| <a id="t48"></a>**Run record** | Запись одного прогона: версии, входы, результат, затраты и вердикт. | B E | M04 |
| <a id="t49"></a>**LLM-as-judge** | Оценка ответа другой моделью; подвержена смещениям и требует калибровки. | B E | M04 |
| <a id="t50"></a>**Baseline** | Простое сравнительное решение без ИИ или с минимальным ИИ, с которым меряют выгоду. | U B E | M01 |
| <a id="t51"></a>**Guardrail** | Ограничитель на входе, выходе или действиях, снижающий риск недопустимого результата. | U B E | M05 |
| <a id="t52"></a>**Prompt injection** | Вредоносная инструкция внутри данных (документ, письмо, ответ инструмента), которую модель принимает за команду. | U B E | M05 |
| <a id="t53"></a>**Lethal trifecta** | Опасное сочетание: доступ к приватным данным, недоверенный контент и способность отправлять данные наружу. | B E | M05 |
| <a id="t54"></a>**Rule of Two** | Правило: в одной сессии разрешать не более двух из трёх свойств trifecta. | B E | M05 |
| <a id="t55"></a>**Data poisoning** | Подмешивание вредных данных в источники знаний или обучения. | B E | M05 |
| <a id="t56"></a>**HITL** | Human-in-the-loop: точка, где человек одобряет действие до его выполнения. | U B E | M05 |
| <a id="t57"></a>**Tenant isolation** | Разделение данных разных клиентов или подразделений, исключающее утечку между ними. | B E | M05 |
| <a id="t58"></a>**Trace** | Пошаговый след работы агента: вызовы модели и инструментов с временем и результатом. | B E | M06 |
| <a id="t59"></a>**Observability** | Возможность понять по логам, метрикам и трассам, что происходит в системе и почему. | B E | M06 |
| <a id="t60"></a>**SLO** | Целевой уровень качества сервиса, например доля успешных ответов за срок. | B E | M06 |
| <a id="t61"></a>**Runbook** | Пошаговая инструкция для оператора при типовом сбое или инциденте. | B E | M06 |
| <a id="t62"></a>**Fallback** | Запасной безопасный путь при ошибке, таймауте или недоступности модели. | B E | M05 |
| <a id="t63"></a>**Cost per accepted outcome** | Затраты, делённые на число результатов, принятых проверкой или человеком; ошибочные прогоны входят в числитель. | B E | M07 |
| <a id="t64"></a>**Prompt caching** | Повторное использование неизменной начальной части запроса для снижения цены и задержки. | E | M07 |
| <a id="t65"></a>**Model routing** | Выбор модели по сложности и цене задачи. | B E | M07 |
| <a id="t66"></a>**TCO / ROI** | Полная стоимость владения и возврат инвестиций; считаются с учётом проверки, поддержки и ошибок. | B E | M07 |
| <a id="t67"></a>**Operating model** | Описание ролей, ответственности и процессов, по которым организация использует и контролирует ИИ. | U B E | M08 |
| <a id="t68"></a>**Fixture** | Заранее подготовленный синтетический набор данных и окружение для упражнения или проверки. | B E | M00 |

Всего терминов: 68. Якоря имеют вид `#t01`…`#t68`; новые термины добавляются в конец, чтобы ссылки не ломались.
