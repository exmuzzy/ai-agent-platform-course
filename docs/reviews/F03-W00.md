Это противоречит охвату классического ML и мультимодальности, а также различению workflow/DAG. Исправление: модель определить как обученную систему преобразования входов в прогноз/выход, текстовый LLM назвать частным случаем; токен определить как единицу представления входа/выхода, для текстового LLM обычно фрагмент текста; workflow определить как заранее заданную логику шагов, ветвлений и повторов, где модель необязательна. Сохранить существующие якоря.
- **A-002, minor, противоречивый expected-output.** `docs/fixture-contract.md:85,87,94,105`: enum `outcome` не содержит `tampered`, хотя ниже он используется как outcome; `forbidden_effects` содержит проверки `trace_lacks/state_unchanged`, но правило требует, чтобы «все forbidden_effects не наступили», что допускает инверсию положительной проверки. Исправление: определить отдельный `verdict` с `tampered` либо добавить значение в outcome и описать его приоритет; написать однозначно «все проверки required и forbidden_effects возвращают true; запрещённые эффекты отсутствуют».

## B: W00

- **B-001, major, валидные KC отвергаются контрактом.** `site/content-contract.json:18` использует `^KC-[AB][0-9]{2}$`. Автоматическая проверка выявила 40 существующих отвергаемых ID из групп Q/O/D/E. Исправление: `^KC-[ABQODE][0-9]{2}$` плюс проверка фактического существования ID по каталогу; добавить позитивные тесты минимум по одному ID каждой группы и негативный тест несуществующего номера.
- **B-002, major, неполный контракт идентичности и прогресса.** `site/content-contract.json:10–19,94,136,156–165,226–258`: route ссылается на quiz ID, но его pattern не определён; progress допускает только lesson/lab/quiz/case, не question/activity. Вопрос имеет собственную integer version, но прогресс хранит только версию unit; activity своей версии не имеет. Невозможно однозначно выполнить требование `docs/course-website.md:46–48` о question IDs и сбросе результата изменённого вопроса, а также восстановить частично выполненный lab. Исправление: определить quiz ID; добавить question/activity записи или вложенные результаты с ID, версией, результатом и attempts; задать activity version; определить агрегирование lab/quiz по текущим ролевым обязательным элементам и critical-вопросам, в том числе пустому набору. Альтернатива для quiz: явное правило обязательного bump quiz version при любом изменении вопроса, но question IDs в экспорте всё равно нужны по исходному требованию. Добавить тесты изменения одного вопроса/активности, неполного lab и запрещённого сочетания kind/state; неожиданные поля должны отклоняться, а не только перечисляться в forbidden_fields.
- **B-003, major, потеря прогресса при обычной навигации без storage.** `docs/site-architecture.md:13,28,32` и `site/content-contract.json:258` совмещают отдельные HTML-страницы с памятью текущей страницы и необязательным localStorage. При запрете storage переход «далее» уничтожает память предыдущего документа; предупреждение только перед закрытием страницы недостаточно для последовательного маршрута. Исправление: выбрать и описать конкретный механизм. Например, сохраняющая состояние клиентская навигация в общем документе при наличии JS с полноценными статическими прямыми ссылками как fallback; либо обязательное предупреждение и явный export/import при каждом переходе, который уничтожает несохранённое состояние. Первый вариант предпочтителен для нормального обучения. В QA добавить «storage запрещён: урок → практика → quiz → progress; результаты предыдущих шагов сохранены или потеря заранее явно предотвращена». Нельзя молча делать localStorage обязательным.
- **B-004, major, allowlist не замкнут по ссылкам.** `docs/site-architecture.md:24` требует падения сборки для ссылки вне allowlist, но `site/content-contract.json:264–276` включает документы, которые уже ссылаются за её пределы. Примеры: `docs/learning-paths.md:5,7,51` ссылается на kernel-learning-and-development, course-website, harness-baseline и harness-course-map; `docs/kernel-proposals/KP-01-reproducible-delivery.md:3` ссылается на harness-baseline. Все эти документы отсутствуют в allowlist. Исправление: для каждого такого назначения решить «добавить после privacy review» или «при сборке заменить внутреннюю авторскую ссылку понятным нессылочным пояснением/публичной разрешённой страницей». Описать детерминированное правило преобразования, а не вручную копировать тексты. После этого тестом проверить замкнутость опубликованного графа; не расширять allowlist до всего docs или research.
- **B-005, minor, разрешение каталога не равно принятому контенту.** `site/content-contract.json:264–285` разрешает целые modules/paths/cases/labs/fixtures и не задаёт отдельного publish manifest или статуса принятия файла. В них могут находиться brief, промежуточные evidence, hidden/holdout либо произвольные побочные файлы. Исправление: разрешать только явно перечисленные publish entries/required_files принятого модуля, добавить исключения для hidden/holdout/private grader, временных файлов и symlink/path traversal; публичные quiz/solutions оставить как учебную самопроверку, не смешивать с доверенным hidden-грейдером.
- **B-006, minor, HTML-якоря запрещены выбранным renderer.** `docs/glossary.md:7–74` использует `<a id="tNN"></a>`, а `docs/site-architecture.md:12` и контракт запрещают raw HTML. Поэтому заявленные стабильные якоря не будут работать при буквальном markdown-it `html:false`. Исправление: задать разрешённый структурный синтаксис ID и безопасное build-преобразование в якоря либо генерировать их из проверенных term IDs; не включать raw HTML глобально.

Подтверждено:

- **Приватность:** обязательных аккаунтов, backend, персональных API-ключей, скрытой аналитики или отправки ответов нет; hosting logs не обещаны отсутствующими. Browser simulation не выдана за рабочий доступ.
- **Порядок:** W00 задаёт контракт до P00; assessment предполагается генерировать из quiz, а не вести второй ручной текст. Машинный файл валиден как JSON, однако это описательный контракт, не исполняемая JSON Schema.
- **Стек:** в среде `node --version` вернул `v20.20.2`; read-only запрос `npm view markdown-it@15 version --json` подтвердил существование 15.0.0–15.0.3, а `npm view gray-matter version engines license --json` вернул 4.0.3, Node >=6, MIT. Выбор технически реализуем; точные patch-версии и lockfile должны фиксироваться в W01, команды пока корректно названы планируемыми в site/README.
- **Публикация:** GitHub Pages через Actions описан как будущая реализация W01/W02, реальный URL не выдуман, preview не подменяет основной адрес, успешный build не назван полноценной приёмкой. В реализации необходимо сохранить требуемое course-website защищённое environment и deploy именно принятого digest.

## Санитизация и ограничения

Целевые файлы прочитаны и дополнительно проверены эвристикой на пользовательские абсолютные пути, внутренние домены, email-подобные значения и ticket-like identifiers. Реальных клиентов, внутренних хостов, тикетов, сотрудников и путей пользователя не обнаружено; совпадения относятся к синтетическому FAKE-маркеру, SHA-256 и публичному AUDIT ID. Публичные авторы и названия источников не являются утечкой персоналий владельца.

Полного DLP-аудита, выполнения fixtures, установки сайта, браузерного теста и проверки hosted URL не было, они не требуются для этого документального этапа. После исправления major W00 нужна адресная повторная проверка контракта и перехода между страницами; фактический браузерный результат остаётся задачей W01/Q02.
