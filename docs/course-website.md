# Учебный сайт: прохождение курса от начала до результата

Обязательный итог проекта: работающий сайт, на котором сотрудник выбирает маршрут, изучает уроки, выполняет практику, проверяет знания и видит свой прогресс. GitHub хранит исходники и материалы; список Markdown-файлов, лендинг и каталог ссылок не являются готовым учебным сайтом.

Статус этого документа: требования к реализации последующей командой агентов. Сайт пока не создан и не опубликован; отсутствие готовых уроков нельзя скрывать демонстрационными процентами прохождения.

## Минимальный продукт

- **Начало:** понятное описание результата, выбор USER/BUILDER/ENGINEER, входные навыки и кнопка начала или продолжения.
- **Маршрут:** последовательность нужных разделов, условия перехода, доступные материалы и незавершённые задания. USER не обязан читать весь инженерный модуль.
- **Урок:** полный текст на русском, примеры, источники, предупреждения, понятная навигация «назад / далее» и связь с практикой.
- **Практикум:** исходные синтетические данные, инструкция, действия, отрицательный пример, ожидаемый результат и критерии проверки. Кнопка «скачать файл» не заменяет упражнение.
- **Проверка знаний:** интерактивные вопросы, отправка ответа, объяснение ошибки, повторная попытка и отдельная обработка критической ошибки безопасности.
- **Прогресс:** прочитанное, результат теста и выполненная практика различаются; открытие страницы не засчитывает освоение навыка.
- **Итог:** собственный результат по роли, рубрика, ограничения самопроверки и дальнейший шаг применения в согласованной среде.
- **Справочник:** поиск по опубликованным урокам, глоссарий, U01–U12, карта возможностей ядра и объяснение предложений развития с их статусами.

Обязательный путь USER выполняется через браузер без Git, Python и личных API-ключей. Для BUILDER/ENGINEER сайт ведёт практику пошагово, предоставляет учебные файлы и критерии; если задание требует разрешённого локального стенда, это названо до начала, а результат не выдаётся за автоматически проверенный браузером.

Синтетический тренажёр на сайте не является корпоративным интерфейсом harness. Создание нового сценария BUILDER, доказательные тесты ENGINEER и требования по безопасности сохраняются; прохождение теста не подменяет эти результаты.

В этом проекте offline/mock-практика означает отсутствие вызовов реальных моделей и рабочих систем, а не обещание загрузки всего сайта без Интернета. Полностью автономное открытие сайта требует отдельного подготовленного артефакта и проверки; его нельзя подразумевать только из слова «статический».

## Публикация и минимальная архитектура

Базовое решение: статически собираемый сайт в `site/`, публикация из того же публичного репозитория через GitHub Pages. GitHub Pages публикует HTML, CSS и JavaScript из репозитория и поддерживает этап сборки ([GitHub Docs](https://docs.github.com/en/pages/getting-started-with-github-pages/about-github-pages)).

W00 выбирает минимальный статический стек по доступной среде и актуальной документации, фиксирует версии, команды и причины выбора в `docs/site-architecture.md`. Не создавать сервер, базу данных, платную LMS или обязательный LLM API ради навигации и самопроверки; сайт должен быть переносим на другое статическое размещение.

- **Исходники:** `site/` содержит интерфейс, сборщик, схему контента и тесты; build-output не редактируется вручную.
- **Единый контент:** уроки в `modules/`, ролевые материалы в `paths/`, кейсы в `cases/` и принятые справочники подключаются на этапе сборки. Не переписывать их отдельно в компонентах.
- **Контракт:** W00 определяет стабильные lesson/question/activity IDs, роли, версии, ссылки, обязательность и способ оценки; P00 и модульные авторы используют этот контракт.
- **Тесты:** канонические вопросы и объяснения хранятся в `quiz.json` модуля, а соответствующая часть `assessment.md` воспроизводимо генерируется из них. Открытые задания и рубрика остаются отдельными; не поддерживать две вручную расходящиеся версии теста.
- **Allowlist:** сборка включает только принятый учебный контент и необходимые файлы. Исследовательские черновики, задания агентов, `.local/`, сырой аудит, ответы сотрудников и весь checkout автоматически в сайт не копируются.
- **Адреса:** проверить фактический base path, прямое открытие урока, обновление страницы, ссылки, поиск и загрузку файлов на конечном размещении. Не придумывать действующий URL заранее.
- **Зависимости:** lockfile, проверенные права/лицензии, воспроизводимая установка и сборка; без удалённых runtime-скриптов, необходимых для основного обучения.

Конфигурацию публикации готовят в W01 и принимают до Q03. Для GitHub Pages custom workflow использует зависимый от сборки deploy job, необходимые права `pages: write` / `id-token: write` и защищённое окружение; актуальные action versions проверяются при реализации ([GitHub Docs](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)).

Не включать автоматическую публикацию каждого чернового push: выпуск запускается для проверенного кандидата после Q03. Если среда предоставляет `deploy_website`, выдать также работающий preview, но не подменять им основной адрес и подтверждённую публикацию.

## Прогресс и приватность

В первой публичной версии нет обязательной регистрации, хранения профилей сотрудников, рейтинга или отчётности руководителю. Выбор учебного маршрута не является назначением прав в рабочей системе.

Минимальный переносимый режим: состояние текущего прохождения в памяти страницы и явные кнопки «Сохранить прогресс в файл» / «Продолжить из файла». Файл содержит версию схемы и курса, маршрут, lesson/question IDs и статусы/результаты, но не ФИО, email, корпоративные документы или ключи; до закрытия страницы интерфейс честно предупреждает о необходимости сохранения.

Импорт проверяет схему, размер, известные IDs и совместимость версий; не исполняет код или HTML. При изменении вопроса прежний результат не засчитывается автоматически; сброс и замена прогресса требуют понятного подтверждения в интерфейсе. Сайт не должен падать при запрете браузерных хранилищ или работе в iframe.

Автоматическая синхронизация между устройствами, аккаунты, SSO и подтверждённая отчётность требуют отдельного согласованного контура идентификации/хранения и политики данных. Не выдавать файл прогресса или изменяемый клиентский счётчик за защищённую аттестацию; результаты открытой самопроверки не являются дипломом Сколково.

Приложение не должно отправлять ответы и прогресс на сервер или включать аналитику по умолчанию. При этом нельзя обещать полное отсутствие технических логов хостинга: GitHub сообщает о сохранении IP посетителей Pages для безопасности ([GitHub Docs](https://docs.github.com/en/pages/getting-started-with-github-pages/about-github-pages)).

## Безопасная практика

Публичный сайт не запускает команды на Mac, не подключает production harness, не принимает API-ключи, не отправляет реальные письма и не выполняет действия в корпоративных системах. Live-практика остаётся отдельной разрешённой веткой; статус `simulation_passed` не превращается в `approved_environment_passed`.

Контент и импортированные данные обрабатываются как данные: разрешённые форматы и URL, безопасный Markdown, отсутствие исполнения произвольного HTML/JavaScript. Добавить отрицательные проверки вредоносной ссылки, неожиданного поля, слишком большого файла и некорректного прогресса; подтверждения нельзя обходить ради успешного демо.

Результат практикума отмечается как `self_reported`, `auto_checked` или `reviewer_verified` только согласно реально выполненной проверке. У первой версии нет доверенного серверного подтверждения личности: ручная отметка или импорт файла не создают `reviewer_verified`.

## Интерфейс и доступность

Направление: спокойный рабочий учебник, а не рекламный лендинг. Чёткая иерархия, читаемая кириллица, сдержанный цветовой акцент, удобный длинный текст, заметные ограничения и минимальная отвлекающая анимация; без выдуманного официального брендинга Сбера/Сколково.

Проверить ширины 375 px и от 1280 px, клавиатурную навигацию, видимый focus, labels форм, контраст, масштаб 200%, длинные названия, таблицы и блоки кода. У всех интерактивных элементов есть понятный эффект, а состояния ошибки/пустого результата/повторной попытки не скрывают данные.

## Задачи и приёмка

| Этап | Зависимости | Обязательный результат |
|---|---|---|
| W00: контракт сайта | F03 | Архитектура, content/progress schema и ролевые сценарии; без нового общего движка |
| P00/Q00: эталон | F03 и W00 для P00 | M00 и quiz соответствуют веб-контракту; педагогическая проверка не ждёт готового интерфейса |
| W01: реализация сайта | W00, Q00 | Работающий интерфейс на настоящем M00, build/test/deploy pipeline; незавершённый контент не выдан за полный курс |
| Q01: интеграция | Все A01–A09, W01, F04 либо одобренный F04-FIXTURE | Все маршруты, полные материалы и сайт собраны; зафиксированы candidate commit и digest учебного bundle |
| Q02: прохождение | Q01 | Независимый browser dry-run трёх маршрутов и практики; desktop/mobile, прогресс, отрицательные сценарии |
| Q03: приёмка | Q02 | Content, source, privacy, accessibility и проверка фактического build-output |
| W02: публикация | Q03 | Проверенный bundle опубликован; действующий URL, версия, hosted smoke-test и инструкция отката |
| Q04: выпуск | W02 и Q03 | Ссылка «Начать курс», проверенный релиз, ограничения и handoff |

Изменение учебного контента, интерфейса, зависимостей или deployment-конфигурации после candidate commit инвалидирует затронутые проверки. W02 публикует тот же принятый bundle, не пересобирает незаметно другой код; отдельные очищенные evidence/release metadata не требуют бесконечной проверки самих отчётов.

До завершения W02 проверить на размещённом сайте: открытие с чистого браузера, выбор всех трёх маршрутов, прямую ссылку на урок, ответ с объяснением и повтором, упражнение M00, экспорт/импорт прогресса, поиск и скачивание учебного файла. Q02 отдельно проверяет все основные типы страниц и состояния, а автоматические проверки покрывают каждую опубликованную страницу/quiz и отсутствие потерянных секций.

Если публикация или проверка реального URL недоступны, W02 остаётся `blocked`: передать проверенный build и точный blocker, но не объявлять сайт или весь курс готовым. Одна успешная сборка и зелёный CI не доказывают возможность пройти обучение.
