# Архитектура учебного сайта (W00)

Статус: принятое для реализации решение W00 (приёмка независимым reviewer в Q00/Q01). Требования описаны в [course-website.md](course-website.md); машинный контракт контента находится в [site/content-contract.json](../site/content-contract.json).

## Решение

Статический сайт, собираемый из канонических Markdown и JSON, без сервера, базы данных, аккаунтов и внешних runtime-скриптов.

| Область | Выбор | Причина |
|---|---|---|
| Сборщик | Node.js 20 и небольшой собственный скрипт `site/build.mjs` | Node 20 есть в среде сборки и в GitHub Actions; нет тяжёлого фреймворка |
| Markdown | `markdown-it` 15 (MIT) с `html: false`, `gray-matter` для frontmatter | безопасный разбор Markdown, сырой HTML запрещён |
| Страницы | отдельный статический HTML на урок, практикум, тест, кейс, справочник | прямые ссылки и обновление страницы работают без rewrite-правил хостинга; текст доступен без JavaScript |
| Интерактив | vanilla JS (ES modules, без бандлера): квиз, практикум, прогресс, поиск, раскрытие ролевых блоков | нет зависимостей на клиенте, нет внешней загрузки |
| Адреса | только относительные ссылки | сайт работает под любым base path и на любом статическом хостинге |
| Поиск | индекс `search-index.json` строится при сборке; поиск по префиксам слов без внешних библиотек | работает офлайн после загрузки |
| Публикация | GitHub Pages через GitHub Actions из этого же репозитория; запасной вариант `deploy_website` как preview | основной адрес остаётся на Pages |
| Зависимости | `package-lock.json`, `npm ci`, только dev-зависимости сборки (markdown-it, gray-matter) | воспроизводимая сборка |

Команды: `cd site && npm ci && npm run build && npm test`; результат в `site/dist/` (в git не хранится). Локальный просмотр: `npm run serve`, статический сервер без зависимостей.

## Источники контента и allowlist

Сайт собирает уроки из `modules/Mxx-*/`, маршруты из `paths/*.json`, кейсы из `cases/`, справочники из принятых документов. Список разрешённых путей находится в контракте. Исследовательские материалы, `workflow/`, `research/`, задания агентов, отчёты review, `.local/` и всё вне allowlist в bundle не попадают; сборка падает, если ссылка ведёт за пределы allowlist. Текст уроков не дублируется в компонентах.

## Страницы и маршруты

Главная с выбором роли; маршрут `route/{role}` показывает шаги, обязательность и состояние; страницы `m/{Mxx}/lesson-NN`, `lab`, `quiz`, `solutions`; `cases/{Uxx}`; `reference/{glossary,kernel,sources}`; `search`; `progress` (экспорт, импорт, сброс); `downloads` (учебные синтетические файлы). USER видит только пользовательские шаги маршрута; инженерные блоки доступны как необязательное раскрытие.

## Прогресс

Прочитанное, результат теста и практика хранятся раздельно (`read`, `passed`/`failed`, `self_reported`/`auto_checked`). Состояние живёт в памяти страницы; `localStorage` используется только как необязательное удобство и не требуется. Экспорт и импорт файла `course-progress/1` описаны в контракте: нет персональных данных, нет исполнения содержимого, проверка размера и известных ID, несовпавшая версия вопроса не засчитывается, замена прогресса требует подтверждения. Статус `reviewer_verified` в браузере не создаётся. Файл прогресса не является аттестацией.

## Практика M00 в браузере

Практикум задаётся блоком `activity` в `lab.md`: синтетическое обращение, поля для извлечения, сравнение с ожидаемым, сценарий запрещённого действия с обязательным отказом и решение «использовать / исправить / передать человеку». Это имитация, помечается `simulation`, не вызывает моделей и не подключается к рабочему harness.

## Безопасность

Нет отправки данных, аналитики и сторонних скриптов; CSP через meta (`default-src 'self'`); ссылки в Markdown только `https:` и относительные; импорт прогресса обрабатывается как данные; отрицательные тесты: вредоносная ссылка, лишнее поле, большой файл, повреждённый JSON. GitHub Pages может хранить IP посетителей для безопасности (см. [GitHub Docs](https://docs.github.com/en/pages/getting-started-with-github-pages/about-github-pages)); это указывается на странице «О курсе».

## Доступность и проверка

Семантическая разметка, skip-link, видимый focus, labels, контраст, масштаб до 200%, ширины 375 и 1280 px. Автоматические проверки (`node --test`): уникальность и формат ID, соответствие quiz.json схеме, правильные ответы существуют, source_ids есть в реестре, ссылки внутри bundle разрешаются, allowlist, отсутствие запрещённых слов-маркеров. Браузерная проверка выполняется реальным браузером по критериям `qa.must_pass` контракта; зелёный CI ею не заменяется.

## Публикация и откат

W01 готовит workflow `.github/workflows/site.yml` (`workflow_dispatch` и тег релиза, не каждый push); deploy job зависит от build и использует права `pages: write`, `id-token: write`. W02 публикует тот же принятый bundle (сверка digest из `manifest.json`) и проверяет реальный URL. Откат: повторный запуск deploy для предыдущего тега либо отключение Pages. Если Pages недоступен, W02 остаётся `blocked`, а preview через `deploy_website` не выдаётся за основной адрес.

## Что не делает первая версия

Нет аккаунтов, SSO, серверного прогресса, отчётности руководителю, аналитики, запуска команд, подключения production harness, приёма API-ключей. Результаты открытых вопросов не отправляются и не оцениваются автоматически.
