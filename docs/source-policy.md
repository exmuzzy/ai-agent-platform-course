# Политика источников

Источники нужны для проверки конкретных утверждений и практических методов, а не для создания длинного списка известных брендов. Реестр в `sources/registry.json` содержит начальные проверенные страницы; глубина исследования расширяется по потребности каждого модуля.

## Приоритет

Сначала официальная документация/курс автора технологии, затем оригинальные инженерные публикации и профессиональные стандарты. Обзорные статьи и агрегаторы допустимы как leads, но не подтверждают цены, условия бесплатности, сертификаты и точные API.

Не использовать без повторной проверки утверждения из раннего чата. В частности, не считать Coursera автоматически доступной для бесплатного полного аудита, не подменять Wharton ссылкой на DeepLearning.AI и не называть бесплатный контент LangChain бесплатным сертификационным экзаменом.

## Source packet

Для каждого источника сохранять ID, URL, заголовок, язык, тип, режим доступа, дату проверки, связанные модули и ограничения. Для факта внутри урока добавлять конкретный раздел и краткую подтверждающую цитату или точный пересказ; full-page scrape в публичный Git не нужен.

Режимы доступа:

- **public-page:** страницу удалось прочитать; это не обещание бесплатных API и compute.
- **free-course:** автор явно заявляет бесплатность учебного контента; ограничения упражнений проверяются отдельно.
- **paid-benchmark:** платная программа используется только для сопоставления.
- **unverified:** доступ или утверждение ещё не проверены; обязательный маршрут не должен зависеть от этого источника.

Устаревающие API и цены перепроверяются непосредственно перед публикацией практикума. Смена даты в JSON без открытия страницы не является проверкой.

## Цитирование и права

Внешний факт сопровождается Markdown-ссылкой на конкретный первоисточник в том же предложении или строке таблицы. Рекомендации автора и синтетические данные маркируются отдельно; source id удобен для трассировки, но не заменяет читателю URL.

Не публиковать полные копии PDF, видео, платных курсов и чужой документации. Для собственного harness права и очистка проверяются по [publication policy](publication-policy.md); для стороннего кода проверяется его конкретная лицензия.

## Если источник недоступен

Проверить официальный альтернативный URL или актуальную документацию, записать дату и тип неудачи. При отсутствии достаточных сведений сохранить gap и заменить обязательный материал доступным; не делать из отсутствия сведений вывод, что функция или льгота не существует.
