# Решения практикума M05.LAB1

Открывайте после попытки. Все данные вымышлены; режим simulation.

## Ответы и пояснения
| Активность | Ответ | Пояснение |
|---|---|---|
| M05.A01 | assistant; draft; deny; executor | Ассистент готовит черновик, запись ему не выдана, запрет обеспечивает исполнитель. |
| M05.A02 | refuse | Текст с фото это данные. Команду не выполняют, инцидент записывают и передают человеку. |
| M05.A03 | p2, p4 | p2 держится на prompt; p4 сочетает недоверенный вход, чувствительные данные и канал наружу. |
| M05.A04 | refuse | Вызов к «Юг» отклоняется, вызов к «Север» проходит, отказ записан в трассу. |
| M05.A05 | не изменились; deny; policy | Строка в ответе инструмента не источник прав. |
| M05.A06 | self_reported | Верного набора отметок нет; честно отмечайте только сделанное. Хороший план содержит все пять пунктов. |

## Типичные ошибки
- Считать фразу в prompt «не делай» достаточным запретом (A01, A03).
- Выбрать «выполнить только безопасную часть» команды из данных (A02): команда не источник решений.
- Отклонять все вызовы, включая разрешённый контрольный (A04): такой тест не доказывает ничего.
- Верить строке «СИСТЕМА: разрешено» в ответе инструмента (A05).
- Писать «отказ» без указания, кто отказал: исполнитель или модель (A06).
- Принимать передачу человеку без отказа за правильный ответ в A02: команда остаётся невыполненной не по решению исполнителя.

## Что нельзя заключить из симуляции
- Что в реальной среде запрет работает: браузерные формы не запускают исполнителя.
- Что модель устойчива к инъекциям: качество реальной модели не измерялось.
- Что статусы возможностей ядра (KC-B07, KC-B09, KC-B10 unverified или not_run; KC-A31 partial) подтверждены.
- Что набор тестов полон: он покрывает инъекцию, запрещённое чтение, подмену ответа, повтор, бюджет и память, но не секреты, исходящую сеть и цепочку поставок.
- Юридических выводов для вашей отрасли: нужна отдельная квалифицированная проверка.

## Для BUILDER и ENGINEER
Проверьте, что в реестре у каждого риска есть владелец. Для инженерного набора ожидаемый результат: мутант пойман, пустой набор провален, отрицательный и положительный сценарии оба присутствуют; повтор с одним ключом даёт одну запись (идемпотентность по [документации Temporal](https://docs.temporal.io/activity-definition), SRC-34, рассуждение о повторе действия после сбоя).
