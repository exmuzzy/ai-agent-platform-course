# M05. Полномочия, governance и безопасность

Статус: draft. Модуль отвечает на вопрос «что агенту разрешено и как это обеспечено». Главная идея: фраза «модели сказали не делать» не является контролем. Контроль есть там, где опасный вызов отклоняет исполнительный контур, даже когда модель его предложила. Всё практическое выполняется как симуляция (mode: simulation) на синтетических данных вымышленной «Региональной билетной системы». Сквозной кейс: U10 (изображения и голос), см. [кейс U10](../../cases/U10.md).

Оценка времени предварительная, её нужно измерить на пилоте: USER 115–135 минут (L01 35 + L02 40 + практикум 40 = 115, тест до 20 минут), BUILDER 145–165, ENGINEER 175–195.

## Результат по ролям

- USER: отличает правило в тексте от ограничения в системе; не выполняет команды из изображений, аудио и документов; знает, какие действия требуют подтверждения человека и как сообщить об инциденте; читает строку политики и замечает, что она не обеспечена.
- BUILDER: дополнительно составляет матрицу «кто, какое действие, над каким ресурсом, чем обеспечено», заводит риск-реестр с владельцами и набор отрицательных тестов для своей автоматизации.
- ENGINEER: дополнительно различает слои prompt, hook, policy, runtime и ОС, проверяет отказ на уровне исполнителя и читает честный статус возможностей ядра (KC-B, KP-02).

Для USER блоки BUILDER и ENGINEER необязательны.

## Что модуль не обещает

- Не доказывает, что защита работает в вашей реальной среде: статусы возможностей ядра в основном unverified или partial, а практикум идёт в симуляции.
- Не заменяет юридический анализ конкретной отрасли, страны или класса данных и не даёт готовых юридических выводов.
- Не разрешает проверять реальные компании и публичные сервисы без разрешения владельца; red-team выполняется только на песочнице без внешних эффектов.
- Не сводит безопасность к prompt injection: охватывает идентичность и минимальные права, изоляцию арендаторов, секреты, исходящую сеть, песочницу, хранение данных, отравление данных и цепочку поставки.
- Чтение урока не равно освоению навыка: навык подтверждается практикумом и тестом.

## Критерии завершения

- Пройдены уроки M05.L01 и M05.L02 и практикум M05.LAB1.
- Выполнены активности практикума M05.A01 и далее по списку в конце урока M05.L02, включая отрицательные сценарии (запрещённое действие отклонено, повтор не создаёт второй операции).
- Пройден тест M05.Q01–M05.Q10 с порогом по quiz.json; критические вопросы без ошибок.
- Вывод, который нельзя делать: «моя система безопасна». Можно сказать только: «перечисленные отрицательные тесты проходят в симуляции».
