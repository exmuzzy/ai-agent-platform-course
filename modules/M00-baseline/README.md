# M00. Доступ, первая задача и диагностика

Статус: draft. Модуль ведёт от вопроса «как мне получить доступ и что можно загружать» к первой проверенной задаче. Всё практическое выполняется как симуляция (mode: simulation) на вымышленной «Региональной билетной системе».

Оценка времени: для USER 100–120 минут (уроки L01 30 + L02 40 + практикум 40 минут); это предварительная оценка, её нужно измерить на пилоте. Для BUILDER и ENGINEER значения также предварительные.

## Результат по ролям

- USER: умеет задать владельцу доступа нужные вопросы, не загружает запрещённые данные, получает структурированную сводку, сверяет её с источником, отличает факт от догадки, находит внесённую ошибку, отказывается выполнять команду из данных и знает, как позвать на помощь.
- BUILDER: дополнительно превращает первую задачу в карточку автоматизации (минимальный список полей приведён в блоке BUILDER урока L02) и знает, какие возможности шаблонов спросить у владельца.
- ENGINEER: дополнительно различает слои source, runtime и instructions, читает честную матрицу возможностей (по состоянию на дату среза в уроке L01) и отличает unit-test от end-to-end evidence.

Для USER инженерные блоки необязательны.

## Что модуль не обещает

- Не даёт прав доступа ни к каким системам и не заменяет решение владельца доступа.
- Реальный порядок получения доступа в компании не проверен (unverified): модуль не описывает регистрацию, кнопки, порталы и контакты.
- Успешная симуляция не доказывает, что доступ работает в реальной среде.
- Чтение урока не равно освоению навыка: навык подтверждается практикумом и проверкой.

## Критерии завершения

- Пройдены уроки M00.L01 и M00.L02 и практикум M00.LAB1.
- Выполнены активности M00.A01–M00.A05, включая отрицательный сценарий (отказ от команды внутри данных).
- Пройден тест (вопросы M00.Q01–M00.Q10) с порогом по quiz.json; критические вопросы без ошибок.
- Вывод, который нельзя делать: «я умею работать с реальными данными и системами». Это зависит от вашего доступа и правил компании.
