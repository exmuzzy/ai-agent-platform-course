# Проверка знаний модуля M01

Режим: simulation. Все данные и числа синтетические (вымышленный транспортный оператор, сценарии S1-S3). Оценивается способ выбора и обоснования, а не знание реального процесса компании, который не проверялся.

## Тест

Раздел генерируется сборкой из `quiz.json` (10 вопросов, порог 0.7, версия 0.1.0). Перечень: M01.Q01, M01.Q02, M01.Q03, M01.Q04, M01.Q05, M01.Q06, M01.Q07, M01.Q08, M01.Q09, M01.Q10.

Критические вопросы: M01.Q01, M01.Q02, M01.Q03. Ошибка в любом из них блокирует завершение независимо от процента. Вопросы M01.Q09 и M01.Q10 только для BUILDER и ENGINEER (Q10 только для ENGINEER).

## Открытое задание

### Общая часть (обязательна для всех ролей)

Для сценариев S1, S2, S3 выберите один пилот и один явно отклонённый сценарий с причиной. Для выбранного назовите вариант без ИИ, KPI в виде дроби (числитель, знаменатель, период), baseline с датой, владельца процесса и владельца метрики, одно условие остановки по качеству и одно по безопасности, а также как учтены проверка и переделка. Укажите, какие данные вы не стали бы загружать и к кому обратились бы за разрешением.

::: builder
### BUILDER

Артефакт: заполненная карточка пилота из десяти полей и строка сравнения вариантов (процесс, владелец, объём в неделю, вариант без ИИ, выбранный вариант, способ проверки, что считается ошибкой). Допустимые действия системы ограничены режимом советов; внешних действий без подтверждения человеком нет.
:::

::: engineer
### ENGINEER

Артефакт: проверка реализуемости (доступные программно данные и права, тестовый набор с известным ответом, что проверяется без человека) и отрицательный тест на команду в поле заявки. Статус любой возможности ядра берите из каталога (например KC-A11) и при unverified формулируйте как гипотезу. Укажите, что считается провалом отрицательного теста.
:::

## Рубрика

Шкала: 0 отсутствует, 1 описан, 2 воспроизведён, 3 выдержал независимый контрпример. Минимум 2 по каждому обязательному критерию.

| Критерий | Роли | 0 | 1 | 2 | 3 |
|---|---|---|---|---|---|
| Выбор по ценности, риску, проверяемости | все | выбор по эффектности | критерии названы общо | применены к S1-S3 | устоял при новом сценарии |
| Отклонённый сценарий | все | нет | без причины | с причиной | причина устояла при контрпримере |
| KPI и baseline | все | нет или метрика активности | KPI без дроби | дробь с baseline и датой | выдержал проверку на скрытый рост проверки |
| Проверка и переделка в эффекте | все | учтена только генерация | упомянуты | посчитаны | найдены в чужом расчёте |
| Остановка и данные | все | нет | общие условия | качество, безопасность, владелец остановки | учения по остановке описаны |
| Карточка пилота | BUILDER | нет | неполная | десять полей | выдержала контрпример |
| Реализуемость и отрицательный тест | ENGINEER | нет | описаны | воспроизводимы | выдержали контрпример |

### Критические ошибки (блокируют завершение)

- Предложена загрузка реальных данных сотрудников без разрешения владельца данных.
- Выполнена или признана допустимой инструкция из данных.
- Эффект заявлен только по скорости генерации, без проверки и переделки.
- Пилот без baseline объявлен улучшением или нет права остановки.
- Для BUILDER: системе разрешено менять график или вести внешнее действие без подтверждения человеком. Для ENGINEER: утверждение о реализации возможности ядра сверх статуса в каталоге или отрицательный тест, проходящий при выполненной инъекции.

## Ограничения самопроверки

Ответы на открытое задание в браузере не оцениваются автоматически; максимум уровень self_reported. Статус reviewer_verified требует независимого проверяющего и здесь недоступен. Прохождение теста подтверждает знание правил в симуляции, но не умение выбрать пилот в реальной компании. Числа вымышлены, пороги остановки выбирает владелец метрики. Содержательные ответы лежат в `solutions.md`.
